# P3-F real smoke run — 2026-10-13

With the owner's consent in chat, one real managed run against Claude Code via the Agent SDK
0.3.296, in a throwaway git repo (`git init`, one commit), on a separate server (port 7461,
`ACP_MODE=live ACP_MANAGED=on`, temp `ACP_DATA_DIR` and an empty temp `ACP_CLAUDE_DIR`, so nothing
under the real `~/.claude` was read for observation). Driven through the control-panel API exactly
as the UI does (CSRF token, the same routes). Aggregates only.

- **Budget tokens used:** lead 15,504, worker 14,357 (of 50,000 each). Most of it is the first turn's
  cache write of the system prompt.
- **Repository:** the merge commit is on `main`, the working tree is clean, `hello.txt` holds exactly
  the requested line, and the worker's worktree and `acp/*` branch were removed after the merge.
- **Database (ADR-0015 check):** the test phrase appears exactly twice in a full dump, in the

- **Logs:** no line contains chat or task text.

## Findings

1. **The lead did not request review on its own** within 20 s of the worker finishing, despite being
   asked to in the first message; a second owner message ("please request review now") worked.
   Follow-up: an owner "Request review" action (route plus button), since the engine already allows
   review requests from the owner.
2. **Session linking shows "none"** in this run because observation pointed at an empty temp Claude
   dir. With the real Claude dir (normal live mode), the transcripts are observed and linked.
3. SDK facts still unverified (P3-B §11.2): shared message ids across agents and `queued_turn_count`
   on every result. Nothing in this run contradicted the adapter's assumptions.
