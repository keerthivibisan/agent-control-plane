## Decisions

- **Expected failures:** `knownGap(fix, tag, title, body)` instead of `it.fails`. It passes only
  while the body fails with its invariant's tag. It fails, saying "make it a plain it()", once the
  body passes, and it fails on any other error. So `pnpm check` stays green, F-1's merge flips
  exactly the gaps it closes, and a broken setup can never hide as an "expected failure".
  Assertions are never weakened.
- **Misbehaviour is applied, not gated, in the server suite.** The test runs the git or
  file-system operation itself, as a Bash command the gate let through would. The invariants check
  what the app guarantees afterwards. Whether the command gets through at all is the adapter table's
  job (hooks, Bash deny rules, `canUseTool`) and the gate's (`allowlist-commands`).
- **A ledger of faults.** Each injected fault's ref changes are accepted as foreign, so `[base]`
  and `[origin]` check only what the app did afterwards. A fault that moved the ticket branch is
  `[ticket-branch]`'s case: every owner path must refuse.
- **Fix labels.** Before F-1 merged, the labels were `F-1` (what its brief named) and `follow-up`.
  Since F-1 merged, every remaining gap is `F-2` (coordinator, 2026-10-24).
- **F-1's reset is in `assertOwnerCanFinish`.** When the ticket branch moved outside the app,
  `movedOutside.tip` must show it. Then POST `/api/runs/:id/ticket-branch/reset` with
  `{ from: tip }` must return 200, the branch must be back at the recorded tip, and
  `movedOutside` must be gone. The finish then continues as before.
- **The adapter table checks F-1's own function.** Each row also checks F-1's
  `checkGitCommand`, so the guard's reading of the command and the built SDK options must agree.
  The workers' and testers' deny rules must hold every `GIT_DENY_RULES` entry. The rule model
  stays as a model of how Claude Code matches rules.

## Findings

**Before F-1** (63 known gaps: server 12, orchestrator 5, adapter 46):

- the lead could not discard a failed seal;
- the Full auto sandbox did not cover the repository's common git directory;
- there was no command guard.

**F-1 flipped 52 of them into plain tests:**

- server 6: lead discard after a branch change ×4, a worktree left on the ticket branch, the
  sandbox's git directories;
- engine 1;
- adapter 45: all 13 branch-changing commands, 21 of the 22 disguised spellings, and all 11
  other repository writes.

The cases that expected `needs-owner` after a branch change now expect `decision`. That is
F-1's behaviour, in which the lead may discard; no assertion was weakened.

**Still gaps (12, all `F-2`):**

- **Unbounded replacement helpers (server ×2, engine ×2).** This holds after branch-changed
  seals, which can now be discarded, and for discard-and-replace.
- **"Try again" on `ticket-branch-moved` merges (server ×1, engine ×1).**
- **Lead discard for `invalid-workspace` seal failures (server ×2, engine ×1).**
- **A planted `remote.origin.pushurl` receives the owner's push (server ×1).**
- **A harness check that is `git push` or `git checkout` is auto-approved (gate ×1).**
- **New: the guard does not read here-strings (adapter ×1).** `bash <<< 'git checkout main'`
  passes. The Full auto sandbox still stops the write.

Holds today, now guarded by plain tests:

- Owner paths refuse a moved ticket branch.
- Base, other branches and origin never move by the app.
- Planted hooks and config never run in the app's git.
- An unreviewed pushed commit is never forced over.
- Setup outputs and attachment copies are never sealed.
- The owner can always discard and finish.
- Rework limits bound blocked merges.
- The simulator's new invariants hold for all templates and 30 generated graphs.
