## Decisions

- **Expected failures:** `knownGap(fix, tag, title, body)` instead of `it.fails`. It passes only
  while the body fails with its invariant's tag. It fails, saying "make it a plain it()", once the
  body passes, and it fails on any other error. So `pnpm check` stays green, F-1's merge flips
  exactly the gaps it closes, and a broken setup can never hide as an "expected failure".
  Assertions are never weakened.
- **Misbehaviour is applied, not gated, in the server suite.** The test runs the git or
  file-system operation itself, as a Bash command the gate let through would. The invariants check
  what the app guarantees afterwards. Whether the command gets through at all is the adapter table's
  job (hooks, Bash deny rules, `canUseTool`) and the gate's (`allowlist-commands`).
- **A ledger of faults.** Each injected fault's ref changes are accepted as foreign, so `[base]`
  and `[origin]` check only what the app did afterwards. A fault that moved the ticket branch is
  `[ticket-branch]`'s case: every owner path must refuse.
- **Fix labels.** `F-1` only where the F-1 brief names the fix: the branch guard, a lead-discardable
  failure when a worktree left its branch, and the sandbox on the git directories. Everything else
  is `follow-up`.
- **F-1's owner "Reset to the last reviewed commit" has no test yet.** Its route did not exist, and
  guessing it would test an invented API. Add it to `assertOwnerCanFinish` when F-1 lands.

## Findings (known gaps today)

Server: 12. Engine and simulator: 4 + 1 (gate). Adapter: 46. The details and the counts per fix
are in the guide.

- **F-1: the lead cannot discard a change whose seal failed.** Today only the owner can, so a lead
  starts replacements (ACPGIT-3).
- **F-1: the Full auto sandbox does not cover the repository's common git directory.**
  `denyWrite` names only `<worktree>/.git`, which is a pointer file. The repository's `.git` (refs,
  objects, config) is in neither list. This partly answers STATUS's open question: our sandbox
  settings never deny it, so whether the write succeeded depended on Claude Code's sandbox
  defaults.
- **F-1: no command guard at all.** All 13 branch-changing commands and 22 disguised spellings
  pass for helpers and testers in every mode.
- **Follow-up: replacement helpers are unbounded.** This holds after failed seals and for
  discard-and-replace. F-1's discardable failure makes the loop cheaper unless starts are bounded.
- **Follow-up: merges that cannot succeed are offered as retryable.** The server maps
  `ticket-branch-moved` and `ticket-branch-checked-out` to `failed`, and the lead hears "Try again".
- **Follow-up: a planted `remote.origin.pushurl` receives the owner's Push & open PR.**
- **Follow-up: a harness check that is `git push` or `git checkout` is auto-approved** by
  `run-harness-check` in auto-edits and Full auto.
- **Follow-up: lead discard for `invalid-workspace` seal failures, and the guard policy for commit,
  stash, rebase, merge, tag, remote, config and worktree add.**

Holds today, now guarded by plain tests:

- Owner paths refuse a moved ticket branch.
- Base, other branches and origin never move by the app.
- Planted hooks and config never run in the app's git.
- An unreviewed pushed commit is never forced over.
- Setup outputs and attachment copies are never sealed.
- The owner can always discard and finish.
- Rework limits bound blocked merges.
- The simulator's new invariants hold for all templates and 30 generated graphs.
