# Scenario 8 (usage-accounting scenario 11): unknown record types

**Provenance:** synthetic (structure modeled on runtime 2.1.2xx per research note
`docs/research/claude-code-observations-2026-10-10.md`). Record `version`: `2.1.263`. All ids, paths, and text are fake; text is `<redacted>`.

**Proves:** known, ignored record types (`attachment`, `last-prompt`, `queue-operation`, `file-history-snapshot`, `file-history-delta`, `artifact-comment-monitor`, `artifact-autoreact-ledger`, `system:stop_hook_summary`; ADR-0011, provider-adapters §4.4) emit no event and are counted once each in `diagnostics().ignoredRecords`. Every other non-allowlisted record type (`bridge-session`, `agent-name`, `mode`, `frame-link`, `relocated`, `atis-latch`, `summary`, `system:compact_boundary`, and an invented future type) becomes `record.unrecognized` with only `recordType`. The type names of the ignored and uncertain records come from the P1-F real-data counts (`docs/research/p1-f-real-data-2026-10-10.md`); their other fields here are invented. The `bridge-session`, `artifact-autoreact-ledger`, and `artifact-comment-monitor` records carry fake account and organization ids and a fake `cwd` (`/home/user/never-read`); none of these values may appear in any event, and the never-read `cwd` must not become the session `cwd`. `system` records other than `api_error` are reported as `system:<subtype>`.
